# 日報・経費・拠点現金業務：拠点取りまとめ・差異付き締め・後日訂正

更新日：2026-10-07。ローカル実装仕様。本番の設定・配備・利用確認とは分けて扱う。

## 1. 対象と既存機能

既存 `/expense-settlement` の本人による支出・日次記録、候補確認、未完了事項、報告日時、参照元メモ、保存結果照会を維持する。同じ画面の「拠点の日次取りまとめ・補充・締め」から拠点担当者の業務へ進む。

今回の対象は、拠点単位の取りまとめ、担当指定に基づく代理入力、実補充の記録、最終照合、差異付き締め、役職者の経費訂正、記録ログ。実OCR・実証憑の保存、送金、LINE送信、買取実績の外部自動取込、返金は含めない。

## 2. 決定事項と設定境界

- 入力途中の暫定差額を、最終の原因不明差異と混同しない。
- 全対象者の入力確認後、差異がある場合も注意表示・明示確認・状況メモ・調査担当を残して締められる。原因が判明するまで締めを止めない。
- 締め時点の資料・金額・対象者・明細・補充を保存する。調査事項は締め後も残す。
- 過去日の経費追加・訂正と詳細記録ログの閲覧は役職者だけに許可する。
- 入力担当、支出者、現金取扱者、訂正者を別に記録する。
- 業務上の役職者は既存の `manager` だけから自動判定せず、拠点単位の指定を要する。
- 代理担当の範囲・有効期間・締め可否、照合式、買取金の正本は確認して設定する。production migrationは担当指定・照合設定を一切作らない。
- 日次締め、報告、差異調査完了、返却・返金、訂正後の再承認は独立する。

## 3. 画面・担当・動線

| 工程 | 担当・入力 | 保存・次の操作 | 例外・復帰 |
| --- | --- | --- | --- |
| 個人記録 | 本人。業務日、支出、買取合計、参照元 | 既存日次・明細。人が確認した値だけ集計 | 未確認候補は集計外。既存の結果照会で復帰 |
| 拠点日次作成 | 指定担当。拠点・日付・当日の対象者・確認メモ | 拠点日次と個人日次の関係を保存 | 休み・直帰等はメモを残して対象者を選ぶ。全在籍者を自動選択しない |
| 代理入力 | 指定担当。支出者の日次を選んで入力 | 支出者を維持し、入力者を認証から記録 | 認証対象外の人・別拠点は拒否。未入力と0円を区別 |
| 入力完了 | 指定担当。開始財布額・買取金・参照元・候補確認 | 対象者ごとの入力確認日時を記録 | 明細・日次を変更すると確認を解除。候補があれば完了不可 |
| 補充 | 指定担当。財布、額、日時、実取扱者、記録メモ | 補充実績を保存。関連する未補充を消込 | 依頼を補充とみなさない。部分補充を保持。誤記録は役職者が取消履歴を追加 |
| 最終照合 | 明示的な照合・締め権限者 | 参照／計算金額、実金額、参照資料と設定版を保存 | 設定なしは拒否。入力・補充変更後は再照合 |
| 締め | 明示的な締め権限者 | 一致／差異ありの締めとimmutableなsnapshot | 差異があれば状況・担当・明示確認を要求。全員入力待ちなら完了者を案内 |
| 報告 | 指定担当。実報告日時・メモ | 実日時と登録日時を分ける | 自己記録。LINE送信成功とは表示しない |
| 後日訂正 | 役職者。元業務日、追加／訂正明細、理由 | 変更前後と操作者を保持。締めsnapshotは維持 | 元明細の版競合を拒否。資金移動を再生成しない |
| 差異引継ぎ | 指定担当が未解決一覧を確認、役職者が調査結果記録 | 翌日を含めて未解決事項を表示 | 調査結果保存で締め時の差額を書換えない。訂正後再承認は未有効 |

URLの `branchDayId` で拠点日次へ直接アクセスできる。戻る・進む・再読込に対応し、対象外IDは別日次へ切り替えない。未保存入力は離脱確認する。画面に金額・氏名をURLとして出さない。

## 4. 権限とログ

`expense_cash_permissions` は組織・拠点・membershipごとに `officer` / `delegate`、`can_close`、有効期間を持つ。全APIで有効なmembership・機能フラグ・拠点担当指定を確認する。system_adminには業務本文を返さない。

| 操作 | officer | delegate |
| --- | --- | --- |
| 拠点取りまとめ・代理入力・補充記録 | 可 | 指定期間内で可 |
| 最終照合・締め | `can_close` が必要 | `can_close` が必要。初期の合成設定では不可 |
| 補充誤記録の取消・経費後日訂正 | 可 | 不可 |
| 詳細な記録ログ | 可 | 不可 |
| 差異調査の結果記録 | 可 | 不可 |

初期の役職者指定は業務確認済み設定として別途投入する。アプリ利用者が自己昇格するAPIは設けない。local seedだけ、架空の管理者をofficer、架空の査定員を締め不可delegateとして明示指定する。これは全支店の権限運用を確定する設定ではない。

操作イベント本文は拠点専用DBへ保存し役職者APIだけから返す。通常のリクエストログ・監査メタデータには自由記述・金額詳細を複製しない。

## 5. 金額・状態の契約

### 照合方式

1. `external_reference`：確認済み資料から入力した金庫参照額と実金額を比較する。自動集計の正本を決めた意味ではない。資料名・対象範囲を必須にする。
2. `vault_ledger_v1`：明示的に採用した拠点だけ、`金庫開始額＋金庫への外部入金−金庫からの外部出金−正味の財布補充額` を使う。財布からの買取・経費を金庫から再控除しない。外部出金に財布補充を含めない。

今回のlocal seedは1を使う。2は合成データの統合テストで検証する。未知の式を選ぶfallbackはない。設定・版が変わった場合は再照合が必要。

### 状態

拠点日次：`open → closed_balanced / closed_difference`。

個人の入力確認、照合、報告、差異解決は別フィールド／記録。入力・補充・対象者が変わると照合版を無効化する。閉じた日の通常入力は拒否し、役職者の訂正へ誘導する。

差異付き締めでは、原因を確定できなくても「原因調査中」と担当者を記録して進める。締め時のsnapshot/hashは不変。訂正は現在の経費集計へ反映するが、資金移動・締め時の実金額・締め時の差額を自動的に変更しない。

未補充は実補充と結び付ける。部分補充は未補充のまま残し、全額補充時だけ解消する。同一補充の再送は1件。取消は元補充の反対記録を1件だけ追加する。支払元が個人立替の明細は会社財布の経費合計へ入らない。

## 6. API・DB・再試行

既存expense APIを維持し、次を追加する。

- `GET /api/v1/expense-branch-options`
- `GET/POST /api/v1/expense-branch-days`
- `GET /api/v1/expense-branch-days/:id`
- `GET /api/v1/expense-branch-days/:id/logs`（役職者専用）
- `POST /api/v1/expense-branch-days/:id/actions/:action`
- `GET /api/v1/expense-branch-operations/:key?operation=...`

actionは `roster / entry / ready / transfer / reverse-transfer / reconcile / close / correct / report / resolve` のallowlist。更新は `expectedLockVersion`、冪等キー、認可、監査を経由する。同じ組織・拠点・業務日の書込みを直列化し、本人の明細変更と締めの競合も防ぐ。

追加migration：`0066_expense_branch_closing.sql`。既存0058・0059・0065は変更しない。権限、照合設定、拠点日次、対象者、補充実績、操作イベント、締めsnapshot、未解決事項を追加。全テーブルにorganization RLS。APIロールは設定変更権限・イベントやsnapshotの更新削除権限を持たない。

通信失敗時は同じキー・同じ本文を再送する。sessionStorageには操作キー・操作種別・対象ID・開始時刻だけ保持する。再読込後は結果照会。保存済み・結果不明を区別し、48時間超過時や本文が失われた場合に新しいキーで自動再登録しない。保存成功後の再取得失敗は、保存を繰り返さない。

## 7. 確認が必要な設定

| 確認 | 決めるもの | 未決でも進める範囲／止める操作 |
| --- | --- | --- |
| 買取金の正本と拠点残高式 | 参照資料・集計元・金庫／財布の範囲 | 手入力記録は可能。未設定の自動照合は不可 |
| 役職者・代理担当者・締め担当者 | 拠点指定と有効期間、代理締め可否 | 合成権限でlocal試験。実利用者への自動付与はしない |
| 当日の現金業務対象者 | 休み・直帰・入力繰越の範囲 | 取りまとめ担当が明示選択し理由記録。勤怠から自動決定しない |
| 訂正後の再確認・再報告 | 訂正版の承認完了条件 | 訂正と履歴保存は可能。再承認完了・再報告済みとはしない |
| 個人立替の返金・日末現金返却 | 実施者・方法・時点 | 経費・締めから自動実行しない |

## 8. 受入条件

- 代理入力でも支出者・入力者・業務日を保持する。
- 未確認候補・未入力がある人を入力完了にしない。0円は未入力と区別する。
- 入力途中は暫定値を表示し、全対象者入力後に最終照合できる。
- 未補充と原因不明差異を別表示し、補充を経費や買取支出へ二重計上しない。
- 差異なし／差異ありの両方で締められる。差異ありは状況・担当・確認を必須にする。
- 締めと本人編集の同時実行、二重クリック、保存直後の通信断でもsnapshotと明細が矛盾しない。
- 翌日経費追加後も元業務日と締めsnapshotを維持し、現金支出や補充を再生成しない。
- 代理担当はログ閲覧・後日訂正できない。期限切れ・他拠点・他組織・フラグOFFは拒否。
- 390pxとPC、Chromium/WebKit、戻る・再読込、axeで検証する。

検証結果は実装報告の当日欄へ記載する。本書の受入条件だけでは実行済み・本番対応済みを意味しない。

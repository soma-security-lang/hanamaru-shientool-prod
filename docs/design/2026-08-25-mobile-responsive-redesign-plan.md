# 買取支援ツール モバイル優先レスポンシブ再設計計画

- 文書日: 2026-08-25
- 対象: GCP版 買取支援ツール Web
- 基準画面: Smartphone 390 × 844 CSS px
- 対象SCR: SCR-001〜020
- 状態: 実装・ローカル検証完了／GCPリリースGate合格

## 1. 目的と完成状態

スマートフォンから利用する査定員が、訪問登録、PDF確認、訪問準備、録音、文字起こし、AI振り返りまでを迷わず完結できる画面へ再設計する。

現在の実装は768px未満でサイドバーを下部ナビゲーションへ切り替え、Tableをカードへ変換している。一方、PCの2〜3ペインをスマートフォンで縦に積み直している画面が多く、一覧と詳細、原本と抽出結果、会話と分析結果の関係が分かりにくい。今回の修正では、単なる縮小や折り返しではなく、スマートフォン用の情報順序と画面遷移を定義する。

完成状態は次のとおりとする。

- 現場業務はスマートフォンだけで完結できる。
- 標準の下部ナビゲーションは「ホーム／訪問／振り返り／知識／その他」の5項目とする。
- スマートフォンでは複数ペインを同時表示せず、一覧から詳細へ段階的に移動する。
- 各画面の主要操作は原則1つとし、下部の操作領域から実行できる。
- ブラウザの戻る操作で、直前の一覧、検索条件、選択状態、スクロール位置へ戻れる。
- 管理画面は確認、承認、停止、再試行などの主要操作を維持し、高密度な長文編集と一括設定だけをPC推奨とする。
- PCの2〜3ペイン構成と業務密度を維持する。
- 既存Route、API、DB、認証方式、RBACを変更しない。
- SCR-001〜020、HTML、テスト、画面画像のdriftを0にする。

## 2. 現行スマートフォンUIの問題

### 2.1 グローバル動線

- 下部ナビゲーションはCSS上5列固定だが、管理権限を持つ利用者には最大6項目が表示される。
- 「買取支援AI」「振り返りチェックシート」などのラベルが長く、390pxで判読性が落ちる。
- 研修、管理、アカウント操作の優先度が同列で、現場業務の導線が埋もれる。
- 上部バーの通知操作は実通知一覧ではなくホームへ遷移し、操作結果を予測しにくい。

### 2.2 複数ペインの縦積み

- 訪問一覧は、案件カードを選択した後に同一ページ下部の詳細まで移動する必要がある。
- PDF取込は、原本、抽出フォーム、確定操作が縦に離れ、照合の往復が多い。
- 文字起こしは、録音状態、品質警告、音声、全発話編集が1ページに連続する。
- AI振り返りは、根拠発話と分析結果が上下に分離し、相互確認しづらい。
- 知識検索は、カテゴリ、検索結果、本文が縦に並び、選択後も長いページが残る。
- ロールプレイは、シナリオ、チャット、評価が連続し、現在工程が分かりにくい。

### 2.3 操作と状態保持

- PC用の上部主要操作とスマートフォン用のSticky操作が混在している。
- 画面内の選択状態がURLへ反映されず、ブラウザバックや再読込で復元しにくい。
- 検索結果から詳細を開いた後、一覧の検索語、絞り込み、スクロール位置へ戻る契約がない。
- ソフトウェアキーボード表示時に、Sticky操作と入力欄が重ならないことを保証するテストが不足している。

### 2.4 検証証跡

- 390pxの画像生成は存在するが、保存済み画像の一部が利用者情報の読込画面で止まっている。
- 横スクロール検査は代表4画面に限定され、全20画面を対象としていない。
- スマートフォンのWebKit、ソフトウェアキーボード、横向き、200% zoomの受入検査が不足している。

## 3. モバイル優先設計原則

### 3.1 情報設計

1. 画面を開いた直後に「現在地」「状態」「次の操作」を認識できるようにする。
2. スマートフォンでは1画面1目的とし、論理的に異なるペインを同時表示しない。
3. 一覧、詳細、編集、確認は段階表示し、ブラウザ履歴へ反映する。
4. 重要情報を上部、主要操作を親指の届く下部へ配置する。
5. 説明文より、状態、対象、実行結果、復旧導線を優先する。
6. 長文は省略せず、目次、Accordion、Tab、Sheetを使って移動量を減らす。
7. PC用機能を非表示にして終わらせず、スマートフォン用の代替操作またはPC推奨理由を提示する。

### 3.2 視覚仕様

- 背景: 淡いニュートラル。
- データ面・フォーム面: 不透明な白。
- Material: App Bar、Bottom Navigation、Sheet、Sticky Actionに限定する。
- Mobile gutter: 16px。
- Mobile section gap: 16px。
- Compact control gap: 8〜12px。
- 本文: 16px、line-height 1.6。
- 補助情報: 13〜14px。12px未満を業務情報へ使用しない。
- 画面見出し: 22〜24px。
- セクション見出し: 17〜18px。
- 操作領域: 最低44 × 44 CSS px。
- 主要ボタン: 高さ48〜52px。
- App Bar: 56pxを基準とする。
- Bottom Navigation: 64px＋`env(safe-area-inset-bottom)`。
- Sticky Action: 64pxを基準とし、Bottom Navigationの直上へ配置する。
- Focus: 2px以上の明確なoutlineを表示する。

### 3.3 モーション

- 押下フィードバック: 120ms。
- ペイン切替: 220ms。
- Sheet・Dialog: 220〜320ms。
- 通常遷移にバウンスを使用しない。
- `prefers-reduced-motion`では移動をなくし、100ms以下のopacity変化へ置き換える。
- 処理時間が不明な非同期処理へ数値進捗を表示しない。

## 4. レスポンシブ区分

| 幅 | 区分 | ナビゲーション | コンテンツ構成 | 検証基準 |
|---:|---|---|---|---|
| 320〜359px | 最小対応 | Bottom Navigation | 1カラム。文言折返しと200% zoomを優先 | 320px |
| 360〜767px | Smartphone | Bottom Navigation | 1カラム、1ペイン、Sticky Action | 360／390／430px |
| 768〜1023px | Tablet | 72px Navigation Rail | 1〜2ペイン、8カラム | 768／834px |
| 1024〜1279px | Compact PC | 240px Sidebar | 2ペイン、必要時3ペインを縮退 | 1024px |
| 1280px以上 | PC | 240px Sidebar | 12カラム、2〜3ペイン | 1440px |

追加条件:

- 高さを`100vh`へ固定せず、`100dvh`とコンテンツ最小高を使い分ける。
- iOSのsafe area、アドレスバー伸縮、画面回転へ対応する。
- Smartphoneで本文領域の横スクロールを発生させない。
- PDF、音声波形、差分、Chartなど内部スクロールが必要な要素は、スクロール対象と代替表示を明示する。
- TabletはSmartphoneの拡大版にせず、一覧＋詳細など関連性の高い2ペインを許可する。

## 5. グローバルナビゲーション

### 5.1 標準下部ナビゲーション

| 表示 | Route | 対象 |
|---|---|---|
| ホーム | `/` | AI支援、直近作業 |
| 訪問 | `/visits` | PDF登録、訪問準備、録音、文字起こし |
| 振り返り | `/reviews` | 振り返り入力、結果、履歴 |
| 知識 | `/knowledge/talks` | トーク、フロー、用語、価格、マニュアル、法務 |
| その他 | 画面内Sheet | 研修、管理、所属、アカウント、ログアウト |

仕様:

- 標準業務利用者は常に5項目とする。
- 権限のない機能は「その他」内にも表示しない。
- `system_admin`や承認専任者など通常業務本文へアクセスできない利用者は、許可された管理機能だけを最大5項目で構成し、案件本文へのリンクを生成しない。
- Active状態は色、アイコン、ラベルの太さで示す。
- Bottom Navigationの上にToastを重ねない。
- 「その他」は`dialog`を使ったBottom Sheetとし、Escape、背景押下、閉じる操作、focus trap、focus restoreへ対応する。

### 5.2 Mobile App Bar

- ルート直下は画面名、所属の短い表示、補助操作を表示する。
- 下位画面は戻る、画面名、Overflow操作を表示する。
- 戻る操作は履歴があれば`router.back()`、直接URLアクセス時は機能の親Routeへ移動する。
- 実機能がない通知アイコンは表示しない。
- ログアウトは「その他」へ移動する。

### 5.3 訪問工程ナビゲーション

Smartphoneでは横長の全工程Tabを常設せず、`CompactVisitStepper`で現在地を表示する。

```text
訪問支援  2 / 5
PDF確認 → 訪問前チェック → 録音・文字起こし → 振り返り作成 → 結果確認
```

- 現在工程と直前・直後工程だけを表示する。
- 完了工程はCheckアイコンと文言で示す。
- 未完了工程への先行遷移はAPI状態に従い抑止し、理由を表示する。
- Tablet・PCでは従来の工程Navigationを維持する。

## 7. URL・戻る操作・状態保持

既存Routeは変更しない。次の任意QueryをUI状態として使用する。

| Query | 用途 | 例 |
|---|---|---|
| `view` | 表示中ペインまたは工程 | `?view=fields`、`?view=detail` |
| `selected` | 選択中の案件・コンテンツ・履歴ID | `?selected=<id>` |
| `q` | 検索語 | `?q=金券` |
| `status` | 状態絞り込み | `?status=ready` |
| `category` | カテゴリ絞り込み | `?category=<value>` |
| `tab` | 既存の意味的Tab | `?tab=retention` |

規則:

- 一覧から詳細、原本から項目確認など、利用者が「進んだ」と認識する切替は`router.push`する。
- 検索語、並べ替え、連続的な絞り込みはdebounce後に`router.replace`する。
- 不正または存在しないQueryは例外にせず、画面既定値へ戻す。
- URLへ顧客名、住所、電話番号、文字起こし本文、AI本文を含めない。
- Desktopでは`selected`を選択ペインへ反映する。`view`は必要に応じて無視し、同じURLで並列表示する。
- 戻る時に一覧を再取得しても、検索条件と選択位置を復元する。
- 一時的な入力内容、音声、文字起こし、AI本文をlocalStorageへ保存しない。

### 8.1 中核業務の詳細動線

#### PDFから訪問登録

```text
/visits
  → PDFから訪問を登録
  → ファイル選択
  → アップロード・抽出状態
  → 10項目を確認
  → 必須項目を修正
  → 内容を確定
  → 訪問前チェック
```

- SmartphoneではPDF iframeをフォームと同時表示しない。
- 「原本を見る」で全画面プレビューへ移動し、戻ると編集位置を復元する。
- 抽出失敗時は「再実行」「別のPDFを選択」を同じ状態Bannerへ表示する。
- 確定操作は、必須項目が有効かつ非送信中の場合だけ有効にする。

#### 録音・文字起こし

```text
録音同意
  → 端末またはDriveから音声選択
  → 取込・STT状態
  → 音声品質確認
  → 発話・話者確認
  → 文字起こし確定
```

- 取込中はページを閉じても継続することを表示する。
- PlayerはApp Bar直下へSticky表示し、発話選択時に対応時刻へ移動できる構造を保つ。
- 発話は音声チャンクごとにAccordion化し、未確認件数を見出しへ表示する。
- 全区間を一度にカード表示しない。
- 品質警告の確認なしに振り返りへ進めない既存制約を維持する。

#### 振り返り

```text
確定済み文字起こしまたは手入力
  → 分析観点を選択
  → AI処理
  → 6領域の結果
  → 根拠発話を確認
  → 確認完了
```

- 分析観点は押下可能なCheckbox Rowとし、選択数を主要操作の近くへ表示する。
- 結果は選択した観点だけ表示する。未選択領域を空カードで残さない。
- 根拠IDがない結果を通常表示へ混在させない。
- 根拠Sheetから戻った際に、開いていた分析領域へfocusを戻す。

## 9. 管理画面のスマートフォン境界

Smartphoneでも維持する操作:

- コンテンツの検索、状態確認、プレビュー、公開状態変更。
- 利用者の検索、権限確認、権限変更、停止。
- Jobの状態確認、詳細、再試行。
- 保存期限、Policy ID、Legal Hold状態の確認。
- 承認差分の確認、承認、差戻し。
- チーム集約値の確認。

PC推奨とする操作:

- 長文コンテンツ本文の本格編集。
- 多数件の一括選択・一括変更。
- 保存期間Policyの複数条件編集。
- 大量データの横断比較・CSV相当の高密度操作。

PC推奨の表示規則:

- 操作を黙って非表示にしない。
- なぜPCが必要か、PCで開くRoute、スマートフォンで可能な代替操作を表示する。
- 緊急停止、再試行、承認など業務継続に必要な操作はPC限定にしない。

## 10. 実装工程

### Stage 1: AppShell・ナビゲーション

- 下部ナビゲーションを標準5項目へ変更する。
- 研修、管理、アカウントを`MobileMoreMenu`へ移す。
- `MobileAppBar`、safe area、Bottom Navigation、Sticky Actionの積層順を固定する。
- Role／capability別の表示を既存RBACと一致させる。

完了条件:

- 360pxでもラベルが重ならない。
- Managerを含め、標準業務Shellは5項目を超えない。
- `system_admin`へ案件本文導線が出ない。
- Keyboard、focus、Escape、Sheet close後focus restoreが成立する。

### Stage 2: 共通レスポンシブ部品

- `ResponsiveMasterDetail`、`MobilePaneTabs`、`MobileFilterSheet`、`ResponsiveDataView`を実装する。
- URL Queryとブラウザ履歴の共通契約を実装する。
- Tableカード変換のlabelとDOM構造を共通化する。
- Soft keyboardとSticky Actionの競合を解消する。

完了条件:

- 一覧→詳細→戻るで検索条件と位置が復元される。
- 非表示ペインへkeyboard focusが移動しない。

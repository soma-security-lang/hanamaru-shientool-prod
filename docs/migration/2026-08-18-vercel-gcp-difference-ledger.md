## 2. 結論

GCP版はVercel版の主要業務機能を欠落なく包含し、PDF起点の訪問登録、録音、文字起こし、根拠付きAI振り返り、RBAC、監査、保存・削除などを追加している。一方で、UI文言には次の差が残る。

- 査定員向け主要機能の欠落は0件。
- 上位ナビゲーションで具体的な業務名が抽象カテゴリへ置き換わった箇所が5件ある。
- 同一機能の表記揺れが6件ある。
- 管理画面に英語の状態値、内部識別子、ハッシュ、`batch`などの実装用語が少なくとも9分類露出している。
- Vercel版の「ロープレ成績」は、個人ランキング・人事評価を避ける方針により、GCP版では「自分の練習履歴」へ意図的に変更されている。
- Vercel版の「880件」は表示値として継承せず、GCP版では実データ由来の件数を表示している。この差は修正対象ではない。

上記は修正前ベースラインである。初回修正は2026-08-19にCloud Runへ公開済み。再比較で残った上位ナビゲーションの短縮語、「困ったときの対応フロー」、API由来`承認batch`は[修正台帳](./2026-08-18-vercel-gcp-correction-ledger.md)のCOR-025で追加修正した。

### 2.1 2026-08-19 公開後再比較

- Vercel公開物はHTTP 200、1,172,142 bytes、SHA-256がEV-002と一致し、比較元の変更はなかった。
- GCP公開revision `hanamaru-pilot-web-00043-yic`は全20 RouteでHTTP 200、主要業務語を配信していた。
- 機能欠落は0件。完全一致しなかった「振り返りチェックシート」「困ったときのフロー集」「訪問前チェックシート」は、COR-025で上位ナビゲーションまたは画面名へ反映した。
- Vercel公開物には「スタッフ管理」という完全一致文字列はなく、「スタッフログイン」が4件存在した。SCR-017の対応元は「スタッフログインと管理機能」として扱う。
- APIデータのカテゴリ名に`承認batch`が含まれると見出しへ露出する経路を検出したため、表示層で「承認対象セット」へ正規化した。

## 10. 優先度別サマリー

### P0：誤操作・誤判断につながる用語

- `draft / published / in_review`等の未翻訳状態。
- `queued / retry_wait / failed`等の未翻訳ジョブ状態。
- `batch`、`Snapshot SHA-256`、`原文hash`を主要操作語として表示していること。
- コンテンツ種別が英語値のまま表示されること。

### P1：業務入口の具体性

- 「AI支援」を「買取支援AI」相当へ具体化する必要性。
- 「用語・価格」で「金券買取価格表」が即認識できないこと。
- 「マニュアル・法務」で「接客」「コンプライアンス」が即認識できないこと。
- 「AIロープレ」と「AIロールプレイ」の表記統一。

### P2：好み・編集上の差

- `集`の有無。
- Vercel版の絵文字中心表現とGCP版のLucideアイコン表現。
- 「チェックシート」を残すか、「チェック」に統一するか。
